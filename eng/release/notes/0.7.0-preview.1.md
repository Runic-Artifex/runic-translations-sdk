# Runic Translations 0.7.0-preview.1

This preview starts the 0.7 line. RMF2 formats lists with `:runic:list` in
.NET and ESM, text references move to transport version 2 so a stored reference
stays readable after the catalog changes (with a version 1 writer for rolling
upgrades), Japanese joins the supported locale families, and generated ESM runs
in Bun without Vite.

Three changes need attention when upgrading from 0.6.0-preview.7; see
[Compatibility](#compatibility):

- Text references are written as transport version 2, which earlier readers
  reject. Upgrade the receivers first, or keep the writers on version 1 until
  they are.
- `new TextArgument(name, null)` no longer compiles: the literal `null` is
  ambiguous between the `string` and the new list overload.
- List placeholders are accepted only in RMF2 contracts.

Install every Runic Translations package on the same exact version,
`0.7.0-preview.1`: the NuGet packages (`Runic.Translations`,
`Runic.Translations.Build`, `Runic.Translations.CommandLine`,
`Runic.Translations.Tooling`, `Runic.Translations.Wpf`,
`Runic.Translations.Templates`), the `dotnet-runic-translations` tool and the npm
packages (`@runic-artifex/vite-plugin-runic-translations`,
`@runic-artifex/translations-svelte`, `@runic-artifex/translations-sveltekit`),
for example `dotnet add package Runic.Translations --version 0.7.0-preview.1`
and `dotnet tool install dotnet-runic-translations --version 0.7.0-preview.1`.
Regenerate ESM output after upgrading the tool. The VS Code and Visual Studio
extensions are attached to this release.

## List formatting

- New RMF2 function `:runic:list` joins a list of strings with the content
  locale's CLDR 48.2 list patterns, as `Intl.ListFormat` does:
  `{$guests :runic:list}` formats `["Ana", "Bo", "Cy"]` as `Ana, Bo, and Cy` in
  English and `Ana, Bo und Cy` in German. `type` is `conjunction` (default),
  `disjunction` or `unit`; `style` is `long` (default), `short` or `narrow`. Both
  options accept a declared string input.
- .NET and ESM use the same generated patterns, including the Spanish `y`/`e`
  and `o`/`u` forms (`Juan e Inés`, `siete u ocho`), so list output is identical
  in both runtimes for every supported locale family.
- Generated C# takes `IReadOnlyList<string>` for a list input and generated ESM
  `readonly string[]`. `TextArgument` has a new list constructor and
  `TextArgumentType.List`. Items are not sorted.
- A list input cannot select a variant. Text references carry list arguments
  from transport version 2 (below).
- Japanese (`ja`) joins the supported locale families, with its CLDR plural
  rules and list patterns. A content locale without list patterns reports
  `RTR0031` when a message formats a list.

## Persisted text references (transport version 2)

- A stored text reference stays readable after the catalog changes.
  `TranslationReferenceResolver.Resolve(snapshot, contractFingerprint, reference)`
  in .NET and the generated ESM `resolveTextReference(value, m, { locale })`
  translate a reference when its key exists with the same argument names and
  types, even if the catalog's contract fingerprint changed, and otherwise show
  the stored fallback text. They return plain text, an outcome (`translated`,
  `fallback`, `failed`) and diagnostics such as `unknown-key` and
  `incompatible-arguments`, and never throw for a catalog change. See
  [cross-process and persisted text references](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.7.0-preview.1/docs/guides/translations/transport.md).
- Transport version 2 tags every argument with its type and adds list
  arguments and message arguments: an argument can be another message of the
  catalog, translated recursively and inserted as a string input, up to 8 levels
  deep and 32 references per tree. `TranslationReferenceArgument` has list and
  message constructors and `Items` and `Message` properties;
  `TranslationTransport` gains `MinimumReadVersion`, `MaximumListItems`,
  `MaximumDepth`, `MaximumReferences`, `MaximumTotalTextLength` (64 Ki
  characters per tree) and `MaximumEncodedLength` (256 KiB).
- `TranslationReference.Parse(string)` and `Parse(ReadOnlySpan<byte>)` read a
  stored reference and reject input above 256 KiB before parsing it; the JSON
  converter measures its input the same way. Readers in both runtimes reject
  duplicate members and a non-integer `version`.
- .NET writes references byte for byte as `JSON.stringify` writes the ESM
  object: non-ASCII text, `<`, `>`, `&`, `'` and `+` stay literal, whatever
  encoder the serializer options name. Strings with a lone surrogate are
  rejected by both writers and readers.
- `TranslationReference.CreateVersion1` and
  `createTextReference(key, inputs, { version: 1 })` still write version 1, with
  scalar arguments only, for receivers that are not upgraded yet.
- Generated `transport.js` adds `createTextReference`, which writes a reference
  from typed inputs, `parseTextReference`, which reads stored JSON text after
  checking its size, and `resolveTextReference`, which also accepts that text.
  `decodeTextReference` and `formatTextReference` accept version 2 and format
  message arguments.
- The resolved text contains stored fallback and argument text verbatim. Render
  it as text, never as HTML.
- The [specification](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.7.0-preview.1/specs/translations/transport-v2.md) and a shared
  .NET and ESM [conformance corpus](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.7.0-preview.1/specs/translations/corpus/transport-v2-persisted-references.json)
  define the wire format and the policy.

## Bun

- Generated ESM is ordinary ES modules and needs no Vite. The
  [operation-history example](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.7.0-preview.1/examples/bun/operation-history/README.md)
  runs a Bun server and a separate process on one generated catalogue, including
  a `bun build` bundle; CI runs it.

## Compatibility

- `new TextArgument(name, null)` no longer compiles (CS0121): the literal `null`
  now matches both the `string` and the new `IReadOnlyList<string>` overload.
  The call always threw `ArgumentNullException`; if you need it, for example in
  a test, cast the argument: `new TextArgument(name, (string)null!)`.
- A list placeholder is accepted only in an RMF2 contract
  (`CompiledTranslationDefinition.FromRmf2Inputs`,
  `TranslationPackMessageContract.FromRmf2Inputs`). The public constructors for
  compatibility-pattern definitions and pack contracts reject
  `TextArgumentType.List`, which those patterns cannot format.
- Text references are written as transport version 2 (`TranslationTransport.Version`
  is now 2). Readers from 0.6.0-preview.7 and earlier reject version 2: the .NET
  `TranslationReferenceJsonContext` throws `JsonException` and every generated
  `transport.js` returns `unsupported-version`. Upgrade and deploy the receivers
  (the .NET package and regenerated ESM) first, or keep the writers on
  `TranslationReference.CreateVersion1` / `createTextReference(..., { version: 1 })`
  until they are. See
  [upgrading from version 1](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.7.0-preview.1/docs/guides/translations/transport.md#upgrading-from-version-1).
- `decodeTextReference` no longer compares a version 2 reference's contract
  fingerprint with the receiver's: it checks the key's own contract. For live
  messages that must come from the same build, call
  `TranslationReference.ValidateCatalog` in .NET or compare the decoded
  `contractFingerprint` with the one `runtime.js` exports. Version 1 is still
  compared.
- `TranslationReferenceArgument` accepts only the spellings every receiver
  accepts: times as `HH:mm:ss`, date-times as UTC `yyyy-MM-ddTHH:mm:ssZ`, and
  decimals without negative zero. Fractional seconds and offsets, which a
  generated ESM receiver always rejected, now throw `ArgumentException` when the
  argument is created. Convert first:
  `value.ToUniversalTime().ToString("yyyy-MM-dd'T'HH:mm:ss'Z'", CultureInfo.InvariantCulture)`
  for date-times and `time.ToString("HH:mm:ss", CultureInfo.InvariantCulture)`
  for times.
- Stored version 1 references keep working where the contract is unchanged.
  Where the catalog's contract fingerprint has changed, they now show their
  fallback text (`fingerprint-mismatch`), or fail without one. A stored version 1
  fractional time or offset date-time does not match its input
  (`incompatible-arguments`), and code that rebuilds typed arguments from such
  stored strings with `new TranslationReferenceArgument(type, value)` throws.
  Version 1 strings are otherwise read as `decodeTextReference` always read
  them, and a version 1 `null` fallback is read as none in both runtimes.
