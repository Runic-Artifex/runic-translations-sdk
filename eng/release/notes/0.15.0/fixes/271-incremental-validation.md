- The language server validates a catalog again after an edit without compiling all of it again: unchanged files are not read again, unchanged messages are not compiled again, and only the checks across locales of the edited messages run again. At 20,000 messages × 10 locales, the validation after an edit to one translation file takes about a quarter of a second, and after an edit to a base-locale file about 0.4 s, instead of a full compile. The diagnostics are the same as a full compile's. In a catalog with a review file, the source fingerprints that mark outdated reviews are computed again only for the edited messages, and the review compiles of a catalog with errors reuse the validation's work, so an edit there is validated in about half a second instead of 2.5–4.5 s. The language server also keeps less memory for a large catalog: about 1 GiB at 20,000 messages × 10 locales after opening a file, instead of 1.3 GiB, with a peak of 1.6 GiB instead of 2.8 GiB.
