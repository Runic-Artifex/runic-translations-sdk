- The language server answers a pending request with `ContentModified` (-32801) only when a change sent while it was
  pending makes its result stale ([#250](https://github.com/Runic-Artifex/runic-translations-sdk/issues/250)). Before,
  any open, change, close, watched-file or configuration event refused every pending document request, so saving a
  file could leave an empty outline, no code actions or a failed `runic/message`. The outline, folding, semantic tokens
  and formatting now depend on their own document only; hover, completion, the code-action listing, `runic/message` and
  `runic/documentInfo` also on `runic.json`, review files and restore state; rename, definition, references, code-action
  resolve and commands also on every file of the catalogs they read, so edits are still never computed from outdated
  text. A watched-file event for an open document whose file holds its text, as after a save, changes nothing. See
  [Protocol](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.15.0/docs/guides/translations/language-server.md#protocol).
