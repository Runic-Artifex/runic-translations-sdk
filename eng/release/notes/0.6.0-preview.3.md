# Runic Translations 0.6.0-preview.3

## Readable C# messages

- The C# generator adds a readable surface next to the encoded members:
  `text.Messages.greeting(name: "Ada")` instead of
  `text.r_6772656574696e67(…)`. Message keys and parameter names that are
  valid C# identifiers are used as written. Any other name keeps its encoded
  `r_<hex>` form for that one parameter. The encoded members are unchanged and
  remain the stable contract.
- Rich-content slots are typed. `text.Messages.checkout_help.Bind(new(guide: link, retry: action))`
  checks the slot names and binding kinds at compile time. A wrong kind, a
  missing or misspelled slot, or another message's slots is a C# error.
  `Rmf2InlineRenderer`, `ToPlainText` and WPF `SetContent` accept the bound
  content.
- New diagnostics:
  - RTR0069 (warning): a message key or slot ID is reserved, or a verbatim name
    clashes with another input's encoded name. That message is left out of
    `text.Messages` and stays available through its encoded member. The class
    names `Messages` and `__readable` skip the readable surface entirely.
  - RTR0068 (warning): the referenced `Runic.Translations` runtime predates the
    readable surface. The generator still emits the encoded members, but
    `text.Messages` is unavailable until the runtime is updated.
  - Change their severity with `NoWarn`, `WarningsNotAsErrors` or a
    `.globalconfig` file. An `.editorconfig` `[*.cs]` section has no effect on
    them.
- The README, the .NET quick start and the Generator, Templates and WPF READMEs
  use the readable form. A new example, `tests/fixtures/translations/readable-consumer`,
  shows typed slots end to end.

## Vite and SvelteKit

- During `vite dev`, saving an `.rmf2` file now updates the text that components
  render. Before, Vite logged a hot update, but the browser kept the previous
  generated messages until a reload. Text computed in a server `load` function
  still updates on reload, as with any SvelteKit server module.
- The generated ESM declarations define a `Locale` union of the catalog's
  locales. `locales`, `baseLocale`, `getLocale`, `getRequestLocale` and the
  source returned by `createLocaleSource` use it, so the source fits
  `MutableLocaleSource<Locale>` without a cast. `setLocale` on that source now
  rejects tags outside the catalog at compile time.
- `@runic-artifex/translations-sveltekit` embeds its sources in its sourcemaps
  and no longer ships declaration maps, so Vite stops warning about missing
  source files on every dev start.
- The ESM guide and the SvelteKit README state that the generated `/server`
  module needs `node:async_hooks` (`AsyncLocalStorage`).
- CI builds the SvelteKit quick start from the packed packages and compiler, and
  checks prerendering, SSR in both locales, a canonical redirect and concurrent
  request isolation.
- New guide: a task-first SvelteKit quick start
  (`docs/guides/translations/quickstart-sveltekit.md`).

## Editor and IDE

- The Visual Studio extension targets Visual Studio 2026 (`[18.0,19.0)`). Its
  native journey passed on Visual Studio Community 2026 18.8.2, including an
  unsaved buffer that survives a restart.
- The RMF2 language server uses open, unsaved buffers again in Visual Studio's
  loose-file mode and in a feature folder below `runic.json`. This was a
  regression in 0.6.0-preview.2.
- With `sourceRoots` configured, an unsaved file joins the compilation only
  where discovery would find it on disk.
- A malformed `runic.json` gives a diagnostic instead of a raw exception in the
  CLI, the language server, MSBuild (RTR0052) and the Translations Editor. This
  covers a non-object root, a mount without `path`, a non-array `sourceRoots`
  and half-saved JSON.
- The Translations Editor runs on Runic SDK 0.7.0-preview.1.

## Upgrading

The generated `Locale` type narrows two declarations that used to take or hold
any `string`:

- `setLocale` on a generated locale source takes a `Locale`. Passing a `string`
  variable no longer type-checks. Use `setLocale(resolveLocale(tag))`: it
  behaves exactly like the old `setLocale(tag)`, which resolved the tag the same
  way, including throwing for an unsupported tag under the strict policy.
- `locales` is `readonly Locale[]`, so `locales.includes(tag)` or
  `locales.indexOf(tag)` with a `string` fails with TS2345. Widen the array,
  as in `(locales as readonly string[]).includes(tag)`, or resolve the tag with
  `resolveLocale`.

Code that annotates the source as `MutableLocaleSource<string>` still compiles.

`InlineMarkupBinding` now derives from a new `MarkupBinding` base record. This
is source-compatible. Package validation reports CP0012 for its
`EqualityContract` and `PrintMembers`, but they are still virtual overrides in
metadata, so compiled callers are not affected.

`dotnet runic-translations validate` now exits 1 with a diagnostic, not 2, for
a malformed `runic.json` (a non-object root or an invalid `sourceRoots` path).
Scripts that treated exit code 2 as "manifest broken" should check for 1.

The Visual Studio extension no longer installs into Visual Studio 2022 (17.x).
