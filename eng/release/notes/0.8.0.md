# Runic Translations 0.8.0

## WPF

- `WpfInlineRenderer` and `WpfDocumentRenderer` accept an already linked
  `Rmf2MarkupContract`, so an app with an inline and a document renderer links
  its catalog's contract once instead of once per renderer:
  `new WpfInlineRenderer(contract, navigate)` and
  `new WpfInlineRenderer(contract, navigate, new WpfInlineRendererOptions { Custom = …, Theme = … })`,
  with `WpfDocumentRendererOptions` for the document renderer. The constructors
  that take the contract JSON are unchanged and now link it once per renderer
  instead of parsing it twice.
- `Rmf2MarkupContract.DeclaresMarkup(name)` reports whether a linked contract
  declares a markup name, such as a custom `shop:badge`, so an adapter can check
  its custom factories against the contract it was given.

## Runic Command Line 0.9.0

- Tested with Runic Command Line 0.9.0. `Runic.Translations.CommandLine` and
  `dotnet-runic-translations` depend on `[0.9.0, 0.10)`, and the editor builds
  against 0.9.0.
- The built-in English and German catalogs of `Runic.Translations.CommandLine`
  translate Command Line 0.9.0's new keys: `help.response-files` and
  `diagnostics.response-file-unreadable`, `-invalid-utf8`,
  `-unterminated-quote`, `-too-deep` and `-cycle`.
- `runic-translations` reads `@file` response files with Runic Command Line's
  opt-in `ResponseFiles()` instead of its own expander, with the same syntax:
  strict UTF-8 with an optional byte order mark, `#` comment lines, Windows
  quoting, nested files relative to their directory, at most 16 levels, and `@@`
  for a literal leading `@`. Help lists `@<file>`, and the shell completions
  complete a file name after `@`.
- `runic-translations` and the Translations Editor write the human output of
  their commands with Command Line outcome presenters
  (`CommandCatalogBuilder.PresentOutcome<T>`) instead of custom outcome sinks.
  Their human output is unchanged, and the JSON envelopes keep their members and
  payloads.

### Behaviour changes

- A response file that cannot be used is reported by Runic Command Line, with
  its message and code, as a usage error (exit code 2): `RCLI1017` cannot be
  read, `RCLI1018` not valid UTF-8, `RCLI1019` unterminated quote, `RCLI1020`
  nested more than 16 levels, `RCLI1021` includes itself. A missing or
  unreadable response file was an I/O failure, `RCLI8205` with exit code 1; the
  other cases were `RCLI8203` with exit code 2.
- The Translations Editor's JSON envelope carries the invocation's own
  `requestId`, as `runic-translations` and every other Runic tool do. It was
  always `runic-translations-editor`.
