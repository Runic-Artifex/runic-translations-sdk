# Runic Translations 0.11.0

Install matching `0.11.0` packages from NuGet and npm: the eight NuGet packages
(`Runic.Translations`, `.Build`, `.CommandLine`, `.Hosting`, `.Tooling`, `.Wpf`,
`.Templates` and the `dotnet-runic-translations` tool) and the three npm
packages (`@runic-artifex/vite-plugin-runic-translations`,
`@runic-artifex/translations-svelte` and `@runic-artifex/translations-sveltekit`).

0.11.0 is the Translations release of the 0.19 release train: Runic Command Line
0.13.0, then Runic Translations 0.11.0, then Runic SDK 0.19.0. The three were
restored, built and run together with warnings as errors before any of them was
published. **`Runic.Translations.CommandLine` 0.11.0 needs Runic Command Line
0.13**, and Runic SDK 0.19's `Runic.Application.Views.Translations` needs
Runic Translations 0.11.

Until 1.0 a new minor may contain breaking changes; this release has the ones in
[Upgrading from 0.10](#upgrading-from-010). See
[Versions before 1.0](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.11.0/eng/release/README.md#versions-before-10).

## Command-line text for Runic Command Line 0.13

The adapter supports exactly one Command Line minor, now 0.13: it depends on
`Runic.CommandLine` `[0.13.0, 0.14.0-0.0)`, and compiles the
`runic-command-line` catalog that Command Line 0.13.0 packs. Command Line 0.13
adds and removes no framework text key and changes no English or German
template, so the adapter's text is the same as in 0.10. What changes is what
the framework passes into that text and which notes help shows:

- **Arguments are named by their placeholder**
  ([runic-cli-sdk#98](https://github.com/Runic-Artifex/runic-cli-sdk/issues/98)).
  The missing-argument error names the argument as the usage line does, by its
  `ValueName` or else its name in angle brackets, and help lists arguments the
  same way:

  ```text
  Das Argument <Container-Pfad> fehlt.
  Aufruf: tool /link <Richtlinie> <Container-Pfad> [Optionen]
  Weitere Informationen erhalten Sie mit "tool /link /?".
  ```

  The German template `Das Argument {$argument} fehlt.` is unchanged; before,
  the same error read `Das Argument container-path fehlt.`.
- **Related options are named by their spelling.** The `[requires: …]` and
  `[conflicts: …]` notes name the option as the app's syntax spells it:
  `[erfordert: /factor]` and `[schließt aus: /l]` with the Windows slash syntax,
  `[erfordert: --factor]` and `[schließt aus: -l]` with the portable one, instead
  of the option IDs (`factor`, `list`).
- **Flags show no default**
  ([runic-cli-sdk#99](https://github.com/Runic-Artifex/runic-cli-sdk/issues/99)).
  An option that takes no value has no `[Standard: False]` note any more. Value
  options keep theirs (`[Standard: 1.5]`).
- **Extended help through a key**
  ([runic-cli-sdk#97](https://github.com/Runic-Artifex/runic-cli-sdk/issues/97)).
  `[Command]` and `[CommandGroup]` take `LongDescriptionKey`, resolved like
  `DescriptionKey` through the application's catalog, with `LongDescription` as
  the fallback. The key `commands.store-show-details` is the message
  `commands.storeShowDetails`; its paragraphs and indented lines are kept.
  `CommandTextContext.ValidateDescriptionKeys` reports an unresolved one as
  `RCLI0023`, as it does for `DescriptionKey`.
- **JSON diagnostics carry the binding ID** (`RCLI1005` and other usage errors
  about one argument or option). Their `arguments` hold the placeholder
  (`["<Container-Pfad>"]`), the `message` is translated as before, and the new
  `binding` member holds the stable ID (`"container-path"`), which no value name,
  syntax or culture changes.

The tests of `Runic.Translations.CommandLine` check each of these in German.

## Tool

`dotnet-runic-translations` runs on Runic Command Line 0.13. Its help lists
arguments by their placeholder, as its usage line does: `runic-translations
locale add --help` shows `<tag>` under `Arguments:` instead of `tag`. Its options
declared no flag defaults and no requires or conflicts, so nothing else in its
help changes.

## Upgrading from 0.10

- **Command-line apps** that use `Runic.Translations.CommandLine`: update
  `Runic.CommandLine` (and `.Spectre`, `.Processes`, `.Testing`) to 0.13
  together with every Runic Translations package to 0.11.0. With Command Line
  0.12 the adapter no longer restores without `NU1608`.
- **Tests that compare German or English CLI output** see the rendered text
  change: `Das Argument <name> fehlt.` instead of `Das Argument name fehlt.`, the
  placeholders under `Argumente:`, the option spellings in `[erfordert: …]` and
  `[schließt aus: …]`, and no default note for flags.
- **Scripts that read the argument ID from a JSON diagnostic's `arguments`**
  read `binding` instead; `arguments` now holds the placeholder.
- **Overrides of `runic-command-line`** need no change: no message changed its
  inputs.
