# Runic Translations 0.6.0-preview.4

## Document messages

- A message whose top level is made of blocks is a document. The built-in
  blocks are `p`, `h level=1..6`, flat `ul` and `ol` (`ol` takes `start` and
  `marker`: `decimal`, `lower-alpha`, `upper-alpha`, `lower-roman`,
  `upper-roman`) and `li`. Paragraphs, headings and list items contain the
  existing inline markup. Translations keep the base locale's content kind and
  block structure; they change text and inline markup only. See the
  [document messages guide](../../../docs/guides/translations/rmf2.md#document-messages)
  and the [document profile](../../../specs/translations/rmf2-document-profile-v1.md).
- New compiler diagnostics `RTR0070` to `RTR0078` (`RTR0075` is reserved and
  not reported). `RTR0077` (a heading skips a level, or the first heading is
  not level 1) is reported for the base locale only.
- .NET: a document message's accessor returns `LocalizedDocumentContent`, or
  `LocalizedDocumentContent<TSlots>` on the readable surface.
  `Rmf2DocumentRenderer` renders it to `DocumentBlock` records with resolved
  options and stable occurrence paths such as `ul[1]/li[2]`. Inline runs
  inside documents carry `InlineMarkupRun.Occurrence`. `Rmf2MarkupContract.Link`
  links the generated contract.
- ESM: document messages return `LocalizedDocument`. `createDocumentRenderer`
  takes `{text, element, block}`.
- Plain text: `ToPlainText` gains overloads that take `Rmf2PlainTextOptions`
  (`AllowActionLabels`, `AnnotateLinkDestinations`, `ListMarker`, `Custom`).
  ESM `toPlainText` takes `listMarker`. Documents are projected with blank lines
  between blocks, `- ` or `n. ` list items and two-space continuation lines.
- Both pack loaders reject a document message whose block structure is not in
  the generated contract as `RTR0023/document-structure-mismatch`.
- Tooling: the language server offers block-aware completion, hover with the
  content kind and locked structure, block folding, a heading outline in
  document symbols, canonical document formatting and a quick fix for
  `RTR0078`. `runic.renderPreview` returns a `blocks` tree for document
  messages, which the Editor renders as a document preview. XLIFF loss entries
  for document messages name the document profile.
- Web document adapters: generated ESM exports `createDomDocumentRenderer`,
  and `@runic-artifex/translations-svelte/document` exports
  `LocalizedDocument` and `documentFactory`. Both render semantic HTML
  (`p`, `h2` and below relative to a `headingBase`, `ul`, `ol` with `start` and
  `type`, `li`; `b`, `i` and `code` for bold, italic and code) with
  `data-runic-occurrence` paths, the effective content locale as `lang` on
  top-level blocks, and the `runic-leaf` class instead of inline styles. Empty
  paragraphs, headings and lists are skipped, as in plain text. DOM `setContent` and `clearContent` and Svelte component
  teardown retire the previous render: retained actions stop calling back and
  retained links lose their `href`. Both render the shared corpus to the
  canonical HTML in `specs/translations/corpus/rmf2-document-v1/html.json`.
- A maintained example, `specs/translations/examples/rmf2-document`, renders
  the bounded #15 document with `createDomDocumentRenderer` and is checked in
  Chromium for keyboard navigation, copying and callback retirement.
- `LocalizedInline` now also removes the `href` of a link that leaves the tree
  and disables a removed action button, which stays inert if re-attached. Its
  inline elements are keyed by name, slot and occurrence. Its markup is
  otherwise unchanged (`span.bold`, `span.italic`).
- The native WPF document adapter is not included yet. Render `DocumentBlock`
  trees with your own code.

## Upgrading

RMF2 runtime ABI 3 replaces ABI 2, and the exported markup contract moves from
version 1 to version 2. Every message entry of the contract gains `content` and
`skeletons`, so the caller fingerprint, the generated C# `CatalogData` and
`Registration`, all generated ESM files, the web module manifest and every
locale artifact change, even in projects without documents.

- Rebuild generated C# and ESM output with the matching compiler. Generated
  code from 0.6.0-preview.3 or earlier fails its `EnsureRmf2RuntimeAbi` check,
  and the Vite plugin rejects a manifest with `rmf2RuntimeAbiVersion` 2.
- Rebuild every external pack. Packs built with 0.6.0-preview.3 or earlier are
  rejected as `RTR0023/markup-contract-version-mismatch`.
- Contract JSON passed by hand to `Rmf2InlineRenderer(string)` or
  `WpfInlineRenderer` must be markup contract v2 with `content`, `skeletons` and
  `contentLocales` on every message. Malformed contract JSON now throws
  `ArgumentException`.
- `p`, `h`, `ul`, `ol` and `li` are now built-in aliases. A project alias with
  one of these names no longer shadows them and reports `RTR0060`; rename it.

See [Migration: markup contract v2](../../../docs/guides/translations/compatibility-retention.md#migration-markup-contract-v2-060-preview4).
