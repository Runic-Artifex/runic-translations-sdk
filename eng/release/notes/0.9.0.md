# Runic Translations 0.9.0

Install matching `0.9.0` packages from NuGet and npm: the eight NuGet packages
(`Runic.Translations`, `.Build`, `.CommandLine`, `.Hosting`, `.Tooling`, `.Wpf`,
`.Templates` and the `dotnet-runic-translations` tool) and the three npm
packages (`@runic-artifex/vite-plugin-runic-translations`,
`@runic-artifex/translations-svelte` and `@runic-artifex/translations-sveltekit`).
`Runic.Translations.Hosting` is new in this release. Tested with Runic Command
Line 0.9.1 (security fixes); `Runic.Translations.CommandLine` requires the
tested minor, `[0.9.1, 0.10)`.

0.9.0 covers the gaps in 0.8. Libraries can ship their own text, and an
application overrides single strings, adds locales and switches one locale for
every catalog, in .NET and on the web. Plurals, ordinals, lists and relative
time support every CLDR locale. Locale negotiation follows CLDR. Dates use the
local time zone. Numbers follow the regional locale and its native digits.
`:currency`, `:unit` and compact notation are new, and right-to-left text is
isolated. Translators get XLIFF profile 3 with placeholders and plurals, a
review file, QA warnings, coverage reports, `.resx` and i18next importers, and
pseudo-locales. The ESM `m` object is tree-shakable.

0.9.0 changes formatted output and behaviour in several places. Read
[Upgrading from 0.8](#upgrading-from-08) before updating. Each pull request's
description and the `PublicAPI` files list the changes in full. Until 1.0 a new
minor may contain breaking changes, and this release still has some; output
changes are allowed until the first `1.0.0-rc.N`. See
[Versions before 1.0](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/eng/release/README.md#versions-before-10).

## Upgrading from 0.8

Update every Translations package, the npm packages and the
`dotnet-runic-translations` tool to 0.9.0 together, then rebuild. The build
regenerates catalog code, and a web build regenerates its output folder. Generated
ESM message modules now import `formatMessage` from `runtime.js`, so regenerate
the whole output folder and never mix files from two releases
([#143](https://github.com/Runic-Artifex/runic-translations-sdk/pull/143)).

### Formatted output changes

Formatted strings change for existing messages. Snapshot tests of formatted text
and stored formatted strings need updating.

- **Dates and times.** Localized `:datetime` styles use the local time zone
  instead of UTC. Date and time styles have the same CLDR length in .NET and ESM:
  short dates show the full year, `long` dates have no weekday, and times show no
  zone name. Use `timeZone=utc` to keep UTC
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130)).
- **Percentages** use the locale's percent pattern, so German writes `50 %`
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130)).
- **Regional formatting.** Numbers, percentages and dates follow the requested
  regional locale (`de-CH`, `en-GB`) when it has the same language and script as
  the text. A user who requests `de-CH` and gets `de` text sees Swiss numbers and
  dates. Unicode extensions of the requested tag are ignored, except `-u-nu`. A tag
  that spells out the default script (`de-Latn-CH`, `en-Latn-US`) formats with its
  region's conventions
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130),
  [#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **Native digits.** Numbers, percentages, dates, times and relative time use the
  locale's CLDR default digits: Bengali `১২,৩৪,৫৬৭.৫`, Persian `۵۰٪`, Arabic (Egypt)
  `٤‏/١١‏/٢٠٢٦`. Request a tag with `-u-nu-latn` (`ar-EG-u-nu-latn`) for Latin
  digits. `{$n :integer useGrouping=never}` also writes the locale's digits and
  minus sign (Persian `‎−۱۲۳۴`, Swedish `−1234`). Use `:string` for codes that
  must stay ASCII
  ([#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **Pinned number data.** Number symbols, grouping and percent patterns come from
  pinned CLDR 48.2 data in both runtimes. They no longer vary with the platform's
  ICU or with `InvariantGlobalization`. Negative zero is written without a sign.
  `es-419`/`es-MX`/`es-AR`, `pt-PT` and `ru-UA` use their own CLDR
  `minimumGroupingDigits`
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131),
  [#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **.NET full dates** use CLDR's weekday case (Latvian `trešdiena`, Mongolian,
  Turkmen, …) and `zh-TW`'s day periods (`凌晨`, `晚上`), as the web runtime does.
  With ICU 78 or later, the .NET `sv-AX` medium date is `4.11.2026`, as on the web.
  Older ICU, including Windows and distribution libicu 72–77, still writes
  `4 nov. 2026`
  ([#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **Relative time** follows CLDR fully. Patterns are chosen per plural category
  and by past or future, and the number uses the locale's separators and digits.
  For example, `in 1.5 Tagen` becomes `in 1,5 Tagen`, `in 1000 days` becomes
  `in 1,000 days`, and `in 1.0 days` becomes `in 1 day`. `numeric=auto` prints
  words for ±2 and for every unit, not only `day` ("the day before yesterday",
  "next month")
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131),
  [#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **Right-to-left isolation.** Catalogs that declare a right-to-left locale
  isolate placeholders with MessageFormat 2's default bidi strategy. Formatted
  strings now contain the invisible characters FSI, LRI or RLI before a
  placeholder and PDI after it. The English fallback for an Arabic request is also
  isolated. English text in an `en`/`ar` catalog is not. Choose the behaviour with
  `runtime.bidiIsolation` (`default`, `on`, `off`) in `runic.json`. Remove the
  characters for comparisons with the new `RemoveIsolates` helpers. LTR-only
  catalogs don't change
  ([#146](https://github.com/Runic-Artifex/runic-translations-sdk/pull/146)).
- **XLIFF export** writes profile 3, so exported files differ from 0.8. See
  [Translator workflow](#upgrading-translator-workflow) below
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134)).

### Locale negotiation

- `resolveLocale` and `SetLocaleAsync` with `ParentsThenDefault` match through
  CLDR likely subtags and parent locales. A tag that fell back to the default
  locale in 0.8 may now match a declared locale: `zh-TW` resolves to `zh-Hant`,
  `de-CH` to `de-DE` (reported as the new `LocaleResolution.Related`), `nb`, `nn` and
  `no` to each other, and legacy codes such as `iw`, `tl`, `mo` and `sh` to their
  replacements
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Closer matches win.** When a catalog declares a locale that is closer than
  the truncated tag, that locale is chosen. For example, `zh-TW` picks `zh-Hant`
  when the catalog declares both `zh` and `zh-Hant`. Ties are broken along the
  request's CLDR parent chain (`en-US-posix` → `en-US`)
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Same-script rule.** Removing subtags no longer reaches a locale of another
  script. `zh-TW` with only `zh` declared, or `sr-Latn-RS` with only `sr`, now
  gets the default locale or the next preference
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **POSIX tags** such as `de_DE` are accepted and normalised, and `und` is
  ignored ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Preference lists** use their own `*FromPreferences` methods.
  `SetLocaleFromPreferencesAsync` (manager and context) and the generated
  `CreateManagerFromPreferences`/`CreateManagerFromPreferencesAsync` take an
  ordered list. They are not overloads of `SetLocaleAsync` or `CreateManager`,
  which still take one tag, because an overload resolved differently for C# 12
  callers. `negotiateLocale(preferences)` (ESM), `LocaleNegotiation` and the
  generated `SupportedLocales` and `ResolveLocale(IEnumerable<string>)` (.NET) are
  new ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **`LocaleChanged` on regional switches.** A manager raises `LocaleChanged` when
  the requested tag changes even if the catalog locale stays (`de` → `de-CH`),
  because numbers and dates now format differently. In a `TranslationContext`,
  every catalog's manager does
  ([#128](https://github.com/Runic-Artifex/runic-translations-sdk/pull/128)).
- `CompiledTranslationProvider` returns a request-specific snapshot view when the
  requested tag differs from the resolved locale. Two tags that resolve to one
  locale no longer return the same snapshot instance
  ([#128](https://github.com/Runic-Artifex/runic-translations-sdk/pull/128)).

### Runtime and generated code (.NET)

- **`SourceHash` and `Rmf2MarkupContract` are no longer `const`.** The generated
  `<Class>Catalog.SourceHash` and `<Class>Catalog.Rmf2MarkupContract` are static
  properties, so .NET Hot Reload can change them. Code that used them where a
  constant is required (an attribute argument, a `case` label, a `const` field)
  must read them at run time
  ([#138](https://github.com/Runic-Artifex/runic-translations-sdk/pull/138)).
- **Second constructor on generated text classes.** Generated text classes add
  `XText(ITranslationContext)` beside `XText(ITranslationManager)`. `new XText(null)`
  still picks the manager constructor. A DI type registration such as
  `AddSingleton<XText>()` becomes ambiguous when the container has both an
  `ITranslationManager` and an `ITranslationContext`; register text classes with a
  factory, as `Runic.Translations.Hosting` does
  ([#128](https://github.com/Runic-Artifex/runic-translations-sdk/pull/128)).
- **Version rule.** Code generated by Translations N runs on `Runic.Translations` N
  or later within the same minor before 1.0, and within the same major from 1.0.
  Packing a library that uses `Runic.Translations.Build` stamps its
  `Runic.Translations` dependency with `[N, next minor-0)`, for example
  `[0.9.0, 0.10.0-0)`, in the package and its symbol package. Multi-targeted
  libraries are stamped too. The next breaking release and its previews fall
  outside the range (NuGet warning NU1608). Set
  `RunicTranslationsStampRuntimeRange=false` to keep the open range. Generated
  code now checks the runtime ABI against the runtime that is actually loaded, and
  the generator accepts a later referenced runtime that still runs its ABIs
  ([#132](https://github.com/Runic-Artifex/runic-translations-sdk/pull/132)).
- **`Runic.Translations.Build` is a development dependency.** A library that packs
  with it no longer lists it as a package dependency, even without
  `PrivateAssets="all"`
  ([#154](https://github.com/Runic-Artifex/runic-translations-sdk/pull/154)).
- With runic.json `overrides`, `translations/overrides/` is no longer part of the
  project's own catalog
  ([#154](https://github.com/Runic-Artifex/runic-translations-sdk/pull/154)).
- **CLI resolver precedence.** `TranslationCommandTextResolver`
  (`Runic.Translations.CommandLine`) resolves locale-first. When German is
  requested, the built-in German text now beats an application override that
  exists only in English. A culture whose language differs from the manager's
  locale is reported once with `Trace.TraceWarning`
  ([#145](https://github.com/Runic-Artifex/runic-translations-sdk/pull/145)).

### Web (ESM, Svelte, SvelteKit, Vite)

- **`m` is a module namespace object.** `messages.js` exports `m` as a namespace
  (`export * as m`), so bundlers keep only the messages you call: one message used
  through `m` bundles 46 KB minified instead of 786 KB on a 759-message catalog.
  It has the same keys and types and still can't be changed, but
  `Object.isFrozen(m)` returns `false`. The internal exports `rmf2Contract` and
  `messageContracts` moved from `runtime.js` to `dynamic.js`
  ([#127](https://github.com/Runic-Artifex/runic-translations-sdk/pull/127)).
- **Shared locale.** A generated catalog without its own resolver follows the
  shared locale when the application sets one, instead of
  `document.documentElement.lang`. `server.js` no longer installs a locale or
  time-zone resolver on its catalog; it reads the request locale from shared
  storage. Removing locale resolvers in any order leaves the latest one installed
  ([#142](https://github.com/Runic-Artifex/runic-translations-sdk/pull/142)).
- A web catalog that uses none of `:currency`, `:unit` or compact notation reports
  overlay or pack messages that use them as `unsupported-function`
  (`RTR0023/unsupported-function` for exact artifacts)
  ([#153](https://github.com/Runic-Artifex/runic-translations-sdk/pull/153)).
- In manifest mode, a manifest inside `node_modules` gets its default
  `virtual.d.ts` under `.runic/translations/` instead of beside it. The Vite plugin
  accepts manifest members that a later compiler adds within ESM ABI 4
  ([#155](https://github.com/Runic-Artifex/runic-translations-sdk/pull/155)).
- `@runic-artifex/translations-svelte` depends on `esm-env`
  ([#142](https://github.com/Runic-Artifex/runic-translations-sdk/pull/142)).

### Upgrading: translator workflow

- **XLIFF profile 3.** `TranslationInterchange.XliffProfileVersion` is 3.
  Placeholders are exchanged as `<ph>`. needs-review is exported as `translated`
  with `subState="runic:needs-review"` (it was `reviewed`). Descriptions are
  readable notes. Profile 2 files are still imported
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134)).
- **Review file `/2`.** Review JSON is written as
  `runic.translations.interchange-review/2`, indented, with per-unit fingerprints:
  editing one message no longer voids the other approvals. `/1` is still read, and
  its approvals are re-confirmed on the next export. `ImportXliff21` reports units
  in `Units` instead of throwing for untranslated or structured units, and
  `ExportXliff21` demotes stale approvals instead of throwing
  `REVIEW-FINGERPRINT`
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134)).
- **New QA warnings.** `RTR0094`–`RTR0098` (plural categories, dropped
  placeholders, formatted booleans, `@maxLength`) and `RTR0090` (stale translation,
  with a review file) are warnings by default. **Projects that treat warnings as
  errors may now fail.** Fix the messages, or set the policy
  (`validation.pluralCategories`, `inputParity`, `formattedBooleans`, `maxLength`)
  to `allow` in `runic.json`
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134),
  [#136](https://github.com/Runic-Artifex/runic-translations-sdk/pull/136)).
- **Exit codes of the new commands.**
  - `status` exits with 0 on catalogs whose translations are incomplete; it
    reports them instead of failing as `validate` does (`RTR0010`). It exits
    with 1 (fault `RTR0099`) when a locale is below `--min-coverage`, and with 2
    when `runic.json`, the base locale or a message's syntax has errors.
  - `import --from resx|i18next` exits with 0 when it skips or refuses single
    messages (each is reported), and fails with `RTR0092` only when the source
    can't be read.
  - `xliff import` exits with 0 when it refuses single units (`RCLI8216`), and
    with 2 when the document can't be used at all. Add `--fail-on refused` to
    exit with 2 and write nothing when any unit is refused.

  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134),
  [#137](https://github.com/Runic-Artifex/runic-translations-sdk/pull/137),
  [#141](https://github.com/Runic-Artifex/runic-translations-sdk/pull/141),
  [#158](https://github.com/Runic-Artifex/runic-translations-sdk/pull/158))
- The `interchange` payload of `runic.translations.tool/1` gains `format`, a
  per-entry `locale`, the `kept` outcome and `units.kept`
  ([#137](https://github.com/Runic-Artifex/runic-translations-sdk/pull/137)).

### Translations Editor state

The editor stores review states in the SDK review file `<catalog>.review.json`
beside `runic.json`. Notes and terminology stay in
`.runic-translations/<catalog>.editor-state.json`, now version 2. On first open,
existing approvals move to the review file; approvals of changed sources become
needs-review. The version 1 state is kept as `<catalog>.editor-state.v1.json`
([#151](https://github.com/Runic-Artifex/runic-translations-sdk/pull/151)).

## Libraries and composition

- **`TranslationContext`.** One requested locale covers an application's catalog
  and its libraries' catalogs, and `SetLocaleAsync` switches them atomically; the
  latest call wins. Generated text classes take a context
  (`new GridText(context)`), and every catalog exposes `XCatalog.Registration`.
  `TranslationContext.SupportedLocales` lists the locales every catalog shows.
  Snapshots, manager events and per-catalog status report `RequestedLocale` and
  `LocaleResolution` (`Exact`, `Related`, `Parent`, `Default`), so a fallback is
  no longer silent
  ([#128](https://github.com/Runic-Artifex/runic-translations-sdk/pull/128),
  [#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Overlays.** `TranslationOverlay.FromPacks` applies application overrides to a
  library catalog. They are checked key by key, so they survive additive library
  releases. They can add locales (with one fallback hop into the library, along
  CLDR parents and never into another script) and resolve locale-first
  ([#128](https://github.com/Runic-Artifex/runic-translations-sdk/pull/128)).
- **New package `Runic.Translations.Hosting`.**
  `services.AddRunicTranslations().AddCatalog(XCatalog.Registration, context => new XText(context))`
  registers a `TranslationContext` with Microsoft.Extensions.DependencyInjection.
  Applications and libraries add their catalogs independently, and only the
  application sets options. The context is a singleton by default (desktop), or
  one per scope with `options.Lifetime = ServiceLifetime.Scoped` (web). With
  overlays, call `await services.InitializeRunicTranslationsAsync()` after
  building the provider. `ITranslationContextFactory` creates further contexts,
  and `AddOverlays` attaches compiled overrides
  ([#133](https://github.com/Runic-Artifex/runic-translations-sdk/pull/133),
  [#154](https://github.com/Runic-Artifex/runic-translations-sdk/pull/154)).
- **Build-time overrides.** `<RunicTranslationsPackCatalog>true</RunicTranslationsPackCatalog>`
  ships a library's catalog sources and contract in its NuGet package. An
  application lists library catalogs in `runic.json` `"overrides"` and writes
  `translations/overrides/<catalog>/<locale>.rmf2`. The build validates these
  files against the packed catalog (`RTR0103`, `RTR0104`) and compiles them into
  `AppTextCatalog.Overlays`, with no packs and no async initialization.
  `overrides[].from` names one package or an array, such as
  `["Acme.Grid", "@acme/grid"]`, so one `runic.json` overrides a library in a .NET
  and a Vite build. `Runic.Translations.CommandLine` packs its
  `runic-command-line` catalog, so an application can override its built-in text.
  `TranslationOverlay.FromCompiled`, `TranslationOverlay.IsCompiled` and
  `TranslationContextBuilder.AddOverlays` are new
  ([#154](https://github.com/Runic-Artifex/runic-translations-sdk/pull/154),
  [#161](https://github.com/Runic-Artifex/runic-translations-sdk/pull/161)).
- **Catalog IDs.** Packing warns when the catalog ID is not the package ID
  (`RTR0105`). `runic-` catalog IDs are reserved for Runic packages (`RTR0106`)
  ([#154](https://github.com/Runic-Artifex/runic-translations-sdk/pull/154)).
- **WPF.** Control libraries name their catalog in XAML with
  `{rt:Message key, Catalog=id}` or
  `rt:TranslationProperties.Source="{rt:CatalogSource id}"`. Applications share
  their context with `TranslationSource.UseContext(context)` and get catalog
  sources with `TranslationSource.ForCatalog(id)`. The XAML build check validates
  named catalogs
  ([#145](https://github.com/Runic-Artifex/runic-translations-sdk/pull/145)).
- **Command line.** `TranslationCommandTextResolver` takes an
  `ITranslationContext` or a `TranslationContextBuilder`. It resolves in the
  invocation's culture and applies overlays of `runic-command-line`, such as
  French packs
  ([#145](https://github.com/Runic-Artifex/runic-translations-sdk/pull/145)).
- **Typed text references (C#).** `AppText.References.key(…)` returns a
  `TranslationReference` with the contract fingerprint, canonical typed arguments
  and the base locale's text as fallback text. Turn the fallback text off with
  `"code": { "referenceFallbackText": false }`
  ([#127](https://github.com/Runic-Artifex/runic-translations-sdk/pull/127)).
- **Hover docs.** Generated C# members and `messages.d.ts` members show the base
  locale's text and the entry's comment, and parameters show their `@param`
  description
  ([#127](https://github.com/Runic-Artifex/runic-translations-sdk/pull/127)).

## Languages and formatting

- **All CLDR locales.** Plural and ordinal selectors, `:runic:list` and
  `:runic:relative-time` support every CLDR locale, including Polish, Russian,
  Ukrainian, Portuguese (with `pt-PT`'s own rules), Arabic, Hebrew, Chinese
  (`zh-Hant`), Korean, Turkish and Finnish. They no longer fail with `RTR0031`
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Locale negotiation** with CLDR likely subtags and parent locales in both
  runtimes. See [Locale negotiation](#locale-negotiation) above
  ([#131](https://github.com/Runic-Artifex/runic-translations-sdk/pull/131)).
- **Local time zone.** `:datetime` takes `timeZone` (`local`, `utc` or an IANA
  ID), and the new styles `medium` and `full`. ESM accepts `Date` and offset or
  sub-second date-time inputs. .NET localized dates no longer throw under
  `InvariantGlobalization`. SvelteKit accepts a `timeZone` for server rendering,
  and ESM has `configureTimeZoneResolver`
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130)).
- **Regional formatting.** Formatting follows the requested locale.
  `getRequestedLocale`, `getMessageLocale`, `formatLocale` and `onFallback` (ESM),
  and `RequestedLocale`, `TryGetContentLocale`,
  `LocalizedTextContent.FormattingLocale` and `TranslationEvents.TranslationFallback`
  (.NET) report what was requested and used. SvelteKit keeps the visitor's
  regional tag (`locals.requestedLocale`, `requestedLocaleFromLocals`)
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130)).
- **Native digits and pinned CLDR 48.2 number data**, identical in .NET and ESM.
  Formatting stays fast whatever locale tags clients request
  ([#148](https://github.com/Runic-Artifex/runic-translations-sdk/pull/148)).
- **Percent** patterns from the locale
  ([#130](https://github.com/Runic-Artifex/runic-translations-sdk/pull/130)).
- **Currency, units and compact notation.** The new MF2 functions `:currency` and
  `:unit`, and compact notation for `:number` (`runic:notation=compact`,
  `runic:compactDisplay`), use pinned CLDR 48.2 data with identical output in
  .NET and ESM. The compiler embeds only the currencies, units and compact
  patterns a catalog uses, for its languages. A currency or unit chosen at run
  time must be listed in `runic.json` `formats` (`RTR0102`); unknown codes and
  units are `RTR0101`. Locale artifacts carry an optional `formatData` member
  ([#153](https://github.com/Runic-Artifex/runic-translations-sdk/pull/153)).
- **Bidirectional text.** Placeholder isolation, `u:dir` for a placeholder's
  direction, and .NET `LocaleDirection` (the same as ESM `localeDirection`). On
  the web, documents mark blocks whose direction differs from the page with
  `dir`, the Svelte packages add `textDirection(locale)`, and SvelteKit replaces
  `%runic.dir%` in `app.html`. See the
  [bidi guide](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/docs/guides/translations/bidi.md)
  ([#146](https://github.com/Runic-Artifex/runic-translations-sdk/pull/146)).

## Translator workflow

- **XLIFF profile 3.** Placeholders are `<ph>` with their MF2 expression, so
  messages with placeholders can now be translated through XLIFF. Import works
  per unit: untranslated, empty and invalid units are skipped or refused, and the
  rest is applied. It tolerates what Crowdin, Weblate, Phrase and Lokalise-style
  tools write. Characters XML can't hold are exported as `<cp hex>`
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134),
  [#139](https://github.com/Runic-Artifex/runic-translations-sdk/pull/139)).
- **Plurals through XLIFF.** Messages with plurals, selects or declarations are
  exchanged with their MF2 syntax protected as codes, so translators edit only the
  variant texts. Exports prefill the plural variants a target language needs, and
  import checks declarations, placeholders and plural categories. Messages with
  markup are still exported as not translatable
  ([#139](https://github.com/Runic-Artifex/runic-translations-sdk/pull/139)).
- **`runic-translations xliff export` and `xliff import`** work without the
  editor, with `--dry-run`, `--source-changed needs-review|refuse` and
  `--fail-on refused`
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134)).
- **Review file and stale translations.** An optional `<catalog>.review.json` is
  shared by the CLI, the editor and the language server. `runic-translations
  review mark` records review state. `validate` warns (`RTR0090`) when a
  translation predates a source change, and stale approvals are exported as
  needs-review
  ([#134](https://github.com/Runic-Artifex/runic-translations-sdk/pull/134),
  [#150](https://github.com/Runic-Artifex/runic-translations-sdk/pull/150)).
- **QA diagnostics.** Plural categories a locale never selects or lacks
  (`RTR0094`, `RTR0095`), a dropped placeholder (`RTR0096`), a boolean formatted
  as text (`RTR0097`), and a message longer than its new `@maxLength` (`RTR0098`;
  XLIFF writes it as `slr:sizeRestriction`). A locale entry in `runic.json` can
  carry its own `validation`, for example to require `de` to be complete while
  `fr` may lag
  ([#136](https://github.com/Runic-Artifex/runic-translations-sdk/pull/136)).
- **`runic-translations status`** reports coverage per locale: translated, served
  by a fallback, missing and stale. `--min-coverage de=100,fr=80` fails CI when a
  locale lags. The JSON payload is `runic.translations.status/1`
  ([#141](https://github.com/Runic-Artifex/runic-translations-sdk/pull/141),
  [#156](https://github.com/Runic-Artifex/runic-translations-sdk/pull/156),
  [#158](https://github.com/Runic-Artifex/runic-translations-sdk/pull/158)).
- **SARIF and more `validate` options.** `validate --sarif <file>` writes SARIF
  2.1.0 with `%SRCROOT%`-relative URIs, and `--project` is repeatable.
  `locale add <tag> [--fallback <locale>]` and `locale remove <tag>` manage a
  project's locales. Unused messages are reported with
  `RunicTranslationsReportUnusedMessages=true` (`RTR0100`, C#) and the Vite
  `reportUnused: true` option
  ([#141](https://github.com/Runic-Artifex/runic-translations-sdk/pull/141)).
- **Importers.** `runic-translations import --from resx|i18next <path>` migrates
  `.resx` files and i18next JSON v4 into `.rmf2` sources. It maps keys,
  placeholders, plural suffixes, nested keys and comments, and reports per message
  what it couldn't map. A re-run adds new messages and keeps existing ones;
  `--overwrite` replaces their text. PO files are not supported; the guides show
  how to convert them. See
  [Migrate from .resx](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/docs/guides/translations/migrate-resx.md)
  and [Migrate from i18next](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/docs/guides/translations/migrate-i18next.md)
  ([#137](https://github.com/Runic-Artifex/runic-translations-sdk/pull/137),
  [#158](https://github.com/Runic-Artifex/runic-translations-sdk/pull/158)).
- **Pseudo-locales.** `runic.json` `pseudoLocales` (`en-XA`, `ar-XB`) generates
  runnable pseudo-locales in development builds: accented, expanded and bracketed
  text, or mirrored right-to-left text, with placeholders and markup kept. They
  are on in MSBuild Debug builds (`RunicTranslationsPseudoLocales`), in Vite's
  `development` mode (plugin option `pseudoLocales`), and with the CLI's
  `--pseudo-locales`. Release builds and packages leave them out
  ([#140](https://github.com/Runic-Artifex/runic-translations-sdk/pull/140)).
- **.NET Hot Reload.** A text-only edit of a `.rmf2` or `.mf2` file under
  `dotnet watch` updates the running app without a restart. Managers republish
  their snapshot, so WPF bindings show the new text. Edits that change the caller
  contract still restart
  ([#138](https://github.com/Runic-Artifex/runic-translations-sdk/pull/138)).

## Web delivery

- **Tree-shakable `m`.** See [Web](#web-esm-svelte-sveltekit-vite) above
  ([#127](https://github.com/Runic-Artifex/runic-translations-sdk/pull/127)).
- **Shared locale channel.** Generated ESM runtimes share a locale channel, so
  `useMessageLocale(locale)` (no runtime argument), `configureSharedLocaleResolver`
  or one `runWithLocale` drives the application's and its libraries' catalogs.
  SvelteKit no longer renders library text in the base locale during SSR.
  `createReferenceResolver` resolves text references of several catalogs
  ([#142](https://github.com/Runic-Artifex/runic-translations-sdk/pull/142)).
- **Overlays on the web.** `installOverlay(artifact)` and `installLocalePack(bytes)`
  from a catalog's `/dynamic` entry install application text or downloaded packs
  over a catalog. They are checked per key and resolved locale-first, with the
  same precedence as .NET, and can add locales. Pages that don't use them bundle
  no overlay code. Overlays that add a language format numbers and dates with
  that language's data
  ([#143](https://github.com/Runic-Artifex/runic-translations-sdk/pull/143),
  [#153](https://github.com/Runic-Artifex/runic-translations-sdk/pull/153)).
- **Over-the-air updates.** `runic-translations generate --emit-json --contract <shipped artifact>`
  builds translation packs for a release that has already shipped, stamped with
  its contract fingerprint. Messages the release can't run are left out, each with
  the reason. See the new guide
  [Ship translation updates without a release](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/docs/guides/translations/ota.md)
  ([#144](https://github.com/Runic-Artifex/runic-translations-sdk/pull/144)).
- **Vite `dependencies: "auto"`.** Library catalogs of npm dependencies
  (`package.json#runicTranslations`, `exports["./runic-translations"]`) are found
  transitively and regenerated with the application's `overrides`, filtered to its
  `locales`, over one shared runtime. Each catalog gets its own declarations. The
  development server regenerates when `overrides` or `locales` change.
  `runic-translations generate` gains `--overrides`, `--locales` and
  `--shared-runtime`
  ([#155](https://github.com/Runic-Artifex/runic-translations-sdk/pull/155)).

## Editor and IDE extensions

### Translations Editor

- Built on Runic SDK 0.16.0. The interface language starts from the operating
  system's preferred languages and is remembered. On Linux, **Browse** uses the
  desktop portal's folder chooser, or zenity without a portal
  ([#135](https://github.com/Runic-Artifex/runic-translations-sdk/pull/135)).
- Opens every catalog of a workspace. Library catalogs of installed packages are
  shown as layers: the library's text is read-only, with your overrides beside
  it. **Override**, **Revert to library** and **Keep override** are available,
  and a marker shows when a library update changes an overridden text. Locales
  the library lacks are shown with their fallback and coverage
  ([#160](https://github.com/Runic-Artifex/runic-translations-sdk/pull/160)).
- Review states in the SDK review file, merged with changes from the CLI and the
  language server. Review data works while a locale misses keys. XLIFF import
  applies units one by one. The quality filter shows the compiler's diagnostics,
  with a quick fix for missing plural variants
  ([#151](https://github.com/Runic-Artifex/runic-translations-sdk/pull/151)).
- The preview formats for a regional locale and a chosen time zone. Pseudo-locales
  use the SDK's generator. Adding a language suggests CLDR locales and shows
  their plural categories. Text direction follows CLDR for every locale
  ([#157](https://github.com/Runic-Artifex/runic-translations-sdk/pull/157)).
- Coverage per language, and **Import from .resx or i18next** with a dry run
  ([#158](https://github.com/Runic-Artifex/runic-translations-sdk/pull/158)).
- Reloading while a setting saves no longer reports an uncaught `BridgeError`
  ([#147](https://github.com/Runic-Artifex/runic-translations-sdk/pull/147)).

### Language server and IDE extensions (preview)

- Diagnostics for every file of an open catalog, linked to the diagnostics
  reference. Hover shows a translation's base text, description and review state

  [#152](https://github.com/Runic-Artifex/runic-translations-sdk/pull/152)).

  Preview Regional Locale** and **Change Preview Time Zone**

- **Visual Studio:** a sample selector in the message preview, plus

## New diagnostic codes

| Code | Severity | Meaning |
| --- | --- | --- |
| `RTR0089` | error | The `Runic.Translations` dependency range could not be written into a packed library. |
| `RTR0090` | warning | A translation (or an override) predates a change to its source or library text. |
| `RTR0091` | warning | The review file (or an override review file) can't be read. |
| `RTR0092` | fault | An `xliff`, `import` or `review` command can't use its document. |
| `RTR0093` | warning | A packed library's `Runic.Translations` dependency has a version format the version rule doesn't handle. |
| `RTR0094` | warning | A plural variant key is never selected in its locale. |
| `RTR0095` | warning | Plural categories of the locale fall to the catch-all variant. |
| `RTR0096` | warning | A translation drops a placeholder the base displays. |
| `RTR0097` | warning | A boolean is formatted as text. |
| `RTR0098` | warning | A message is longer than its `@maxLength`. |
| `RTR0099` | fault | Translation coverage is below `--min-coverage` (`status`). |
| `RTR0100` | info | A message isn't referenced from C# code (`RunicTranslationsReportUnusedMessages`). |
| `RTR0101` | error | A currency or unit isn't in the pinned CLDR data. |
| `RTR0102` | error | A run-time currency or unit has no declared set in `runic.json` `formats`. |
| `RTR0103` | error | An override doesn't match the library catalog. |
| `RTR0104` | error | The library catalog to override isn't available. |
| `RTR0105` | warning | A packed catalog's ID isn't its package ID. |
| `RTR0106` | error | `runic-` catalog IDs are reserved for Runic packages. |

See the [diagnostics reference](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.9.0/docs/guides/translations/diagnostics.md).
