# Runic Translations 0.15.1

Install matching `0.15.1` packages from NuGet and npm: the eight NuGet packages
(`Runic.Translations`, `.Build`, `.CommandLine`, `.Hosting`, `.Tooling`, `.Wpf`,
`.Templates` and the `dotnet-runic-translations` tool) and the three npm
packages (`@runic-artifex/vite-plugin-runic-translations`,
`@runic-artifex/translations-svelte` and `@runic-artifex/translations-sveltekit`).

0.15.1 is a patch release of 0.15.0 with one fix to how external and overlay packs
are loaded. It changes no API. .NET applications get the fix by updating the
packages; code generated with 0.15.0 runs on the 0.15.1 runtime unchanged. Generated
ESM output carries its own runtime, so regenerate it with the 0.15.1 compiler (a
build with the 0.15.1 Vite plugin or `dotnet-runic-translations` does that).

## Fixes

- Loading an external or overlay pack compares its markup contract with the catalog's entry by entry, in .NET and in
  generated ESM, without writing out the version 2 form of a version 3 contract. Its time and memory now grow with the
  size of the pack and the catalog. A version 3 contract must list canonical locales in ordinal order, as many as the
  catalog's version 3 contract does. A pack that does not meet these rules, or that fails to load for any other
  reason, is refused with `TranslationPackException` (`ArgumentContractMismatch` or `Malformed`) in .NET or an
  `RTR0023` result in ESM, so the application's fallback runs. Upgrade if your application loads packs it did not
  build itself; generated ESM output carries the runtime, so regenerate it with this release.
