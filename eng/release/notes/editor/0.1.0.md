# Runic Translations Editor 0.1.0

The first release of the Translations Editor on its own version line (D078). Until now the editor shared the version
of the Runic Translations packages it is built from; from 0.1.0 on it has versions of its own, plain `0.y.z` before
1.0, and releases of its own in this repository, tagged `editor-v<version>`. This release is built from the same
source as Runic Translations 0.16.0, on Runic SDK 0.24.0, and checks spelling in each text's language
([Spell checking](#spell-checking-in-each-texts-language)).

Download the package for your system from the release's assets and check it against its `.sha256` file. The packages
are unsigned: see [Download and install](https://github.com/Runic-Artifex/runic-translations-sdk/blob/editor-v0.1.0/apps/translations-editor/docs/editor-distribution.md#download-and-install)
for the steps on each system, including macOS Gatekeeper and Windows SmartScreen.

## The Translations Editor's list view: palette commands, unsaved marks, and large catalogs ([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225))

The command palette switches between the workbench and the list (**Switch to list view**, **Switch to workbench**),
in English and German. A row of the list whose message has unsaved work, text that differs from the file on disk or a
changed review state, shows the window title's unsaved mark (•) before its path, named "Unsaved changes" for screen
readers; Save and editing the text back to the saved text clear it. The list renders only the rows in view and
measures rows of different heights, so a catalog of 20 000 messages opens in the list in milliseconds instead of
seconds; keyboard navigation, editing row after row with Tab, filters and the remembered view work as before, and
screen readers still hear each row's position in the whole list.

## A side-by-side list for bulk translation in the Translations Editor ([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225))

The editor's toolbar switches between the workbench and a list (D074.1). The list shows the selected language's
messages as rows in the order of the message tree, under their namespaces, with the dotted message path, the source
text, the translation and its state (a hollow square for missing, a filled one for done, a diagonal for outdated). It
follows the sidebar's search and filter, and the selected message stays selected when you switch.

A message whose text is one sentence with placeholders is edited in its row with the same placeholder chips as the
workbench; a missing translation starts empty beside its source text. Up and Down move between rows, Enter edits,
Escape stops editing and Tab goes on to the next row. A message with plural forms, other variants or more structure
shows a summary and opens in the workbench. Edits share the workbench's one save, undo, recovery of unsaved work and
close question, and the density setting applies to the rows. The source language and one-language projects list the
path, the text and the developers' note. The editor remembers the view you chose.

## What changed in the source of a stale review ([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225))

When a source message changes after its translation was approved, the workflow panel of the stale translation shows
the source it was approved for ("Source when marked") next to the current one, with removed words struck through,
added words highlighted and placeholders as chips, beside **Confirm translation** and **Mark needs review**. The text
comes from `<catalog>.review-sources.json`, which the editor, `review mark`, `xliff import` and the language server now
write beside the review file (Runic Translations 0.15.0). An entry recorded by an older tool, without its text, shows
the stale hint without the comparison.

## Spell checking in each text's language

([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225), D074.10, D086.2)

The editor checks spelling itself, in the language of the text being edited, with a Hunspell checker per language from
runic-sdk's `Runic.Spelling` (0.24.0-preview.1). The webview's own checker is off, since it checked a German
translation with the system's English dictionary. Misspelled words get a wavy underline in the pattern box, in a
variant's message source and in the composer's message source. Placeholders, markup and MF2 syntax are never marked.
With the caret in a marked word, the editor shows corrections and **Add to dictionary**. Added words go to a word list
that all Runic applications of the user share.

- **English** (`en_US`, `en_GB`) ships with the editor, and the system's Hunspell dictionaries are used.
- **The system language's dictionary downloads on its own** when a project has that language and no dictionary is
  installed, and the composer says so while it runs. **Editor settings → Download my language's dictionary
  automatically** turns this off.
- **Any other language asks first:** the composer names the dictionary's size and downloads it only after
  **Download**. A failed download installs nothing and offers **Try again**.
- Dictionaries come only from `Runic.Spelling`'s pinned catalog: files at a fixed GitHub commit, each checked by size and
  SHA-256 before it is installed in the folder that all Runic applications share, with its license beside it. These
  downloads are the editor's only network requests
  ([Diagnostics and privacy](https://github.com/Runic-Artifex/runic-translations-sdk/blob/editor-v0.1.0/apps/translations-editor/docs/editor-distribution.md#diagnostics-and-privacy)).
- **Editor settings → Check spelling** turns the marks off.

## The Translations Editor's icon on Linux desktops

`runic-translations-editor desktop-entry install` writes the editor's desktop entry and icon for the current user:
`$XDG_DATA_HOME/applications/eu.runicartifex.TranslationsEditor.desktop` and the icon in the user's hicolor theme
(`$XDG_DATA_HOME` is `~/.local/share` by default). The entry is named after the editor's app ID, and its
`StartupWMClass` and icon name are that ID, so Wayland compositors and X11 desktops show the editor's window with its
icon and list the editor with the applications instead of a generic icon. `desktop-entry uninstall` removes exactly
those files; an entry of the same name that the editor did not write, such as a package's, is neither replaced nor
removed. No launch writes into the home directory. On macOS the editor sets its Dock icon from its packaged icon.

The deb, rpm and AppImage bring their own desktop entry, so `desktop-entry install` is for a source build and the
`.tar.gz` archive.

## Packages for Linux, macOS and Windows

The editor now comes as packages of its own, built from this repository's source by
`.github/workflows/release-editor.yml` and attached to the editor's GitHub release. None needs a .NET runtime, an SDK
or Node.js:

- **Linux (x64):** a deb (Debian, Ubuntu) and an rpm (Fedora), which install the editor in
  `/usr/lib/eu.runicartifex.TranslationsEditor` with its desktop entry, icon and AppStream metadata and depend on the
  system's GTK 4 and WebKitGTK 6; an AppImage, which uses the same system libraries; and a `.tar.gz` archive. The
  editor is a NativeAOT executable, built with runic-sdk's `dotnet runic package`.
- **macOS (Apple silicon):** a disk image with the ad-hoc signed application bundle.
- **Windows (x64):** a self-contained `.zip` with the `runic-translations-editor.cmd` launcher. It is not an MSIX,
  because Windows installs only signed MSIX packages.

Every file has a sibling `.sha256` file, and the archives carry a `package-manifest.json` with the version, channel,
source revision and the SHA-256 of every file. The packages are unsigned (D078.4): there is no paid certificate behind
them. The release workflow installs or extracts each package on a runner of its system and opens the editor's window
before the release is drafted.

## Upgrading

- **The editor's application ID is now `eu.runicartifex.TranslationsEditor`** (it was `eu.runic-artifex.TranslationsEditor`),
  because runic-sdk's packages accept only letters and digits in each part of the ID. It is the GTK application ID,
  the desktop entry's and icon's name and the macOS bundle identifier. If you installed the desktop entry with
  `desktop-entry install` from an earlier build, remove it: run `desktop-entry uninstall` with that build, or delete
  `~/.local/share/applications/eu.runic-artifex.TranslationsEditor.desktop` and
  `~/.local/share/icons/hicolor/*/apps/eu.runic-artifex.TranslationsEditor.png`. The editor's preferences, recent
  projects and drafts are not stored under the ID and stay where they are.

### Behaviour and output changes

- The validation panel no longer shows the project's schema version ("compiler · schema v1"). It names the file
  format only when a project is in an older one, as "Older file format (v1)" for example; project schema 1 is the only
  version so far, so the panel shows nothing there today
  ([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225)).

- Messages are named by their dotted path (`common.cancel`), as `validate` and the diagnostics name them, and the
  message tree and the list group them by namespace
  ([#225](https://github.com/Runic-Artifex/runic-translations-sdk/issues/225)). The editor's bridge contract adds
  `EditorMessageEntry.path` and `EditorDiagnostic.messagePath` for it, without changing existing members.

- Marking a translation reviewed or approved also writes `<catalog>.review-sources.json` beside
  `<catalog>.review.json`, with the source text of each entry. Commit it with the review file; the review file's own
  content is unchanged.

- The Translations Editor's **Browse** dialog for a workspace folder now belongs to the editor window, through the
  window's Runic Desktop file dialogs: the XDG portal's FileChooser parented to the window on Linux, the system folder
  dialog modal for the window on Windows, and a sheet on the window on macOS. In an installed browser (`--browser`) the
  same dialogs open without an owner, and `serve`, which has no window, shows them without one. The `zenity` fallback
  on Linux and the PowerShell and AppleScript dialogs on Windows and macOS are gone: where no dialog can open, for
  example on Linux without a FileChooser portal, the editor asks for the workspace path instead.

- The editor is built on Runic SDK 0.24.0 (NuGet and npm) instead of 0.22.0. With 0.23, on Windows a screen reader's
  announcements are spoken and typed keys reach the page after the screen reader presses a button in it, and the
  editor's executable and window show the editor's icon on Windows; 0.24 brings fixes in the Views runtime, the
  generated clients and the native Desktop server. See the
  [Runic SDK 0.23.0](https://github.com/Runic-Artifex/runic-sdk/blob/v0.23.0/eng/release/notes/0.23.0.md) and
  [0.24.0](https://github.com/Runic-Artifex/runic-sdk/blob/v0.24.0/eng/release/notes/0.24.0.md) notes.

- `--version`, **About & diagnostics** and diagnostic bundles show the editor's own version (0.1.0), its update
  channel and source revision, instead of the Runic Translations version the editor carried before.

## Fixes

- Adding a message under an existing group inserts it into that group instead of writing a second block for the same
  group.
- The editor's visual text box shows keyboard focus with one ring around the box. Its focused text segment no longer draws a second ring inside it; in forced colours, which draw no box ring, the segment keeps its outline.
- When the translations editor's message composer or a quick fix cannot apply a change, it now reports the reason in the editor's language, as typing in a message already did, with the compiler's details attached, instead of a bare English message.
- Previewing a change in the translations editor (a structural change such as adding or renaming a message, or an import) no longer hides a file another program changed just before: the editor still reports it as changed on disk. Only reloading the workspace or applying a change acknowledges outside edits.
- The editor opens a workspace below a symbolic link or junction, such as anything in macOS's `/tmp` or `$TMPDIR` (links to `/private/…`) or a project in a linked `~/Development`, and a workspace folder that is itself a link ([#280](https://github.com/Runic-Artifex/runic-translations-sdk/issues/280)). It works from the folder the links lead to; a link inside the workspace, which a repository could plant, is still refused.
- `validate` says why a workspace could not be opened in words, such as "Translation sources cannot be symbolic links.", instead of the notice's code (`ui_backend_path_link`), and prints the text of the editor's own diagnostics, such as a pending recovery ([#280](https://github.com/Runic-Artifex/runic-translations-sdk/issues/280)).
