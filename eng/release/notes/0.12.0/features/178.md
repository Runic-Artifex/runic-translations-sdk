## A write API for in-page translation editing

([#178](https://github.com/Runic-Artifex/runic-translations-sdk/issues/178))
Under `vite dev`, `@runic-artifex/vite-plugin-runic-translations` offers
`/__runic-translations/message`, so a page can edit a translation in place:
runic-sdk's Runic Inspect selects a text, shows its message in every locale and
writes the edit back.

- **`GET`** reads a message of the application's catalog, or of a library
  catalog regenerated with `dependencies: "auto"`, in every locale: its text as
  authored, its inputs and plural or selector variants, where each locale
  defines it, and the SHA-256 of the file a write changes.
- **`POST`** writes one locale's whole message text (plural, selector, markup
  and document messages as their whole source). It is compiled with the rest of
  the catalog first and refused with its diagnostics (422) when it does not
  compile; a file that changed since it was read is refused (409) with the
  current message. The page then updates in place, as on a save.
- **Source-preserving:** the write goes through `runic-translations serve`,
  which gains `message` and `set-message` requests, and the Translations Editor's
  writer, so only the message's text changes and the file keeps its formatting,
  comments, line endings and order. A locale without the message gets it
  inserted beside the base locale's.
- **Library catalogs:** a write goes to the application's override,
  `translations/overrides/<catalog>/<locale>.rmf2`, by the rules of
  `runic-translations overrides add --key` (with its review entry, and listing the
  catalog in runic.json `overrides` when needed); the installed package is never
  written.
- **On by default, loopback only:** the API exists only on the dev server and
  accepts same-origin requests from the same machine. `inPageEditing: { allow:
  [...] }` or `RUNIC_TRANSLATIONS_EDIT_ALLOW` admit other hosts and networks
  (addresses, IPv4/IPv6 CIDR such as a Tailscale network, host names);
  `inPageEditing: false` turns it off. Vite's host check still applies. Production
  builds are byte for byte the same with or without it.

See "In-page editing API" in the plugin's README and
[In-page translation editing](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.12.0/docs/guides/translations/esm.md#in-page-translation-editing).
