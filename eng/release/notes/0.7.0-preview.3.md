# Runic Translations 0.7.0-preview.3

## Generated C# catalogs

- The generated C# catalog embeds each locale's messages as UTF-8 data and reads
  a locale when a manager or provider first needs it, with the locales it falls
  back to. It used to build every message of every locale in one method, which
  the JIT compiled whole in each process that created a manager: for a catalog
  of about 1,300 messages in two locales, about 300 ms of JIT and 210 MiB peak
  memory before the first message. The same catalog now takes about 90 ms of
  JIT and 60 to 70 MiB, and a process that formats only English never reads
  German. Rebuild to pick up the change; the generated API is unchanged
  ([#87](https://github.com/Runic-Artifex/runic-translations-sdk/issues/87)).
- `CompiledTranslationLocale.CreateDeferred` and
  `CompiledTranslationLocale.ReadRmf2Values` are the runtime side of this, for
  generated code. A catalog with deferred locales validates each one on its
  first snapshot; invalid data fails that snapshot with an
  `InvalidOperationException`. Catalogs built from locales with their values
  are validated in the constructor, as before.
- A `TranslationProject` outside the C# project's directory, such as
  `../Frontend/translations/runic.json`, now builds. Its sources reached the
  compiler under a different path than the project and failed with `RTR0052`.
- New example and guide section: [strings outside the Views](https://github.com/Runic-Artifex/runic-translations-sdk/blob/main/docs/guides/translations/runic-desktop.md#strings-outside-the-views),
  a C# tray process that formats its frontend's catalog and is published with
  NativeAOT in CI.
