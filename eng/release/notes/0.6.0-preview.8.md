# Runic Translations 0.6.0-preview.8

## List formatting

- New RMF2 function `:runic:list` joins a list of strings with the content
  locale's CLDR 48.2 list patterns, as `Intl.ListFormat` does:
  `{$guests :runic:list}` formats `["Ana", "Bo", "Cy"]` as `Ana, Bo, and Cy` in
  English and `Ana, Bo und Cy` in German. `type` is `conjunction` (default),
  `disjunction` or `unit`; `style` is `long` (default), `short` or `narrow`. Both
  options accept a declared string input.
- .NET and ESM use the same generated patterns, including the Spanish `y`/`e`
  and `o`/`u` forms (`Juan e Inés`, `siete u ocho`), so list output is identical
  in both runtimes for every supported locale family.
- Generated C# takes `IReadOnlyList<string>` for a list input and generated ESM
  `readonly string[]`. `TextArgument` has a new list constructor and
  `TextArgumentType.List`. Items are not sorted.
- A list input cannot select a variant. Text references carry list arguments
  from transport version 2 (below).
- Japanese (`ja`) joins the supported locale families, with its CLDR plural
  rules and list patterns. A content locale without list patterns reports
  `RTR0031` when a message formats a list.

## Persisted text references (transport version 2)

- A stored text reference stays readable after the catalog changes.
  `TranslationReferenceResolver.Resolve(snapshot, contractFingerprint, reference)`
  in .NET and the generated ESM `resolveTextReference(value, m, { locale })`
  translate a reference when its key exists with the same argument names and
  types, even if the catalog's contract fingerprint changed, and otherwise show
  the stored fallback text. They return plain text, an outcome (`translated`,
  `fallback`, `failed`) and diagnostics such as `unknown-key` and
  `incompatible-arguments`, and never throw for a catalog change. See
  [cross-process and persisted text references](../../../docs/guides/translations/transport.md).
- Transport version 2 tags every argument with its type and adds list
  arguments and message arguments: an argument can be another message of the
  catalog, translated recursively and inserted as a string input, up to 8 levels
  deep and 32 references per tree. `TranslationReferenceArgument` has list and
  message constructors and `Items` and `Message` properties;
  `TranslationTransport` gains `MinimumReadVersion`, `MaximumListItems`,
  `MaximumDepth` and `MaximumReferences`.
- Generated `transport.js` adds `createTextReference`, which writes a version 2
  reference from typed inputs, and `resolveTextReference`. `decodeTextReference`
  and `formatTextReference` accept version 2 and format message arguments.
- The [specification](../../../specs/translations/transport-v2.md) and a shared
  .NET and ESM [conformance corpus](../../../specs/translations/corpus/transport-v2-persisted-references.json)
  define the wire format and the policy.

## Bun

- Generated ESM is ordinary ES modules and needs no Vite. The
  [operation-history example](../../../examples/bun/operation-history/README.md)
  runs a Bun server and a separate process on one generated catalogue, including
  a `bun build` bundle; CI runs it.

## Compatibility

- `new TextArgument(name, null)` no longer compiles (CS0121): the literal `null`
  now matches both the `string` and the new `IReadOnlyList<string>` overload.
  The call always threw `ArgumentNullException`; if you need it, for example in
  a test, cast the argument: `new TextArgument(name, (string)null!)`.
- A list placeholder is accepted only in an RMF2 contract
  (`CompiledTranslationDefinition.FromRmf2Inputs`,
  `TranslationPackMessageContract.FromRmf2Inputs`). The public constructors for
  compatibility-pattern definitions and pack contracts reject
  `TextArgumentType.List`, which those patterns cannot format.
- Text references are written as transport version 2 (`TranslationTransport.Version`
  is now 2). Regenerate the receivers' ESM before or with the writers: a
  `transport.js` from an earlier release rejects version 2 as
  `unsupported-version`. Version 1 is still read; it is translated only with the
  writer's exact contract fingerprint.
- `TranslationReferenceArgument` accepts only the spellings both receivers
  accept: times as `HH:mm:ss`, date-times as UTC `yyyy-MM-ddTHH:mm:ssZ`, and
  decimals without negative zero. Fractional seconds and offsets, which a
  generated ESM receiver always rejected, now fail when the argument is created.
