# Runic Translations 0.13.0

Install matching `0.13.0` packages from NuGet and npm: the eight NuGet packages
(`Runic.Translations`, `.Build`, `.CommandLine`, `.Hosting`, `.Tooling`, `.Wpf`,
`.Templates` and the `dotnet-runic-translations` tool) and the three npm
packages (`@runic-artifex/vite-plugin-runic-translations`,
`@runic-artifex/translations-svelte` and `@runic-artifex/translations-sveltekit`).

0.13.0 is the Translations release of the 0.21 release train: Runic Translations
0.13.0, then Runic SDK 0.21.0, then the editor extensions from runic-editors
0.21.0. Runic Command Line is not part of this train:
**`Runic.Translations.CommandLine` 0.13.0 needs Runic Command Line 0.13**, as
0.12.0 did. Translations 0.13.0 and Runic SDK 0.21.0 were restored, built and
run together with warnings as errors before either was published.

This is a small release ahead of 1.0. It hardens in-page translation editing on
the dev server, and it applies the API review for 0.13: three names change, so
code and scripts that use them need an edit. It adds no features.

Until 1.0 a new minor may contain breaking changes. See
[Upgrading from 0.12](#upgrading-from-012) and
[Versions before 1.0](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.13.0/eng/release/README.md#versions-before-10).

## Highlights

- **In-page editing is harder to reach from elsewhere.** With
  `server.allowedHosts: true` the dev server's editing API checks `Host` itself,
  and on Linux it accepts a write only from the user running the dev server
  ([details](#behaviour-and-output-changes)).
- **Three renames from the API review:** `TranslationContextBuilder.AddCatalog`,
  `runic-translations xliff import --input` and `RUNIC_DEV_ALLOW` as the only
  name of the editing allow list ([details](#breaking-changes)).

## Upgrading from 0.12

Update every Runic Translations package, NuGet and npm, to 0.13.0 together.
Runic Command Line stays at 0.13.

- **Libraries packed with `Runic.Translations.Build` 0.12** depend on
  `Runic.Translations` `[0.12.0, 0.13.0-0.0)`, so an application on the 0.13.0
  runtime gets NuGet warning `NU1608`. Pack a library update with 0.13.0, as for
  every Runic Translations minor (see
  [Versions](https://github.com/Runic-Artifex/runic-translations-sdk/blob/v0.13.0/docs/guides/translations/libraries.md#versions)).

### Breaking changes

- `Runic.Translations`: `TranslationContextBuilder.Add(registration, options)` is
  now `TranslationContextBuilder.AddCatalog(registration, options)`, the name that
  `IRunicTranslationsBuilder.AddCatalog` of `Runic.Translations.Hosting` already
  has for the same operation. Replace `.Add(` with `.AddCatalog(` where a
  `TranslationContext.CreateBuilder()` chain registers a catalog; the arguments
  and the behaviour are unchanged. Code compiled against 0.12 fails with
  `MissingMethodException` until it is rebuilt.

- `@runic-artifex/vite-plugin-runic-translations` no longer reads
  `RUNIC_TRANSLATIONS_EDIT_ALLOW`, the former name of the in-page editing API's
  allow list. Set `RUNIC_DEV_ALLOW` instead, which takes the same entries and
  which vite-plugin-runic also reads for Runic Inspect. When the old variable is
  set, the dev server logs a warning and ignores it.

- `runic-translations xliff import` takes the XLIFF document with `--input <path>`
  instead of `--source <path>`, which read like a filter on the source-language
  text next to `--source-changed`. `--source` still works as a hidden alias until
  2.0; giving both is an invocation error (exit code 2).

### Behaviour and output changes

- `@runic-artifex/vite-plugin-runic-translations`: with `server.allowedHosts:
  true`, the in-page editing API checks `Host` itself and answers only IP
  addresses, `localhost` and allow-listed host names. On Linux, a write from
  loopback is accepted only when the client belongs to the user running the dev
  server; macOS and Windows log that they cannot tell local users apart. Reads,
  allowed remote clients and the existing write guards are unchanged.

## Release engineering

- The Svelte and SvelteKit packages and the translations editor build with
  `@sveltejs/adapter-static` 4.0.1, which fixes GHSA-jf9x-2fg2-hx4w. It is a
  development dependency only: the published packages don't depend on it, and
  the advisory concerns route config generated for Vercel.
