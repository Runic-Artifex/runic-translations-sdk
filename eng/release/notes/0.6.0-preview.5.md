# Runic Translations 0.6.0-preview.5

## WPF XAML binding

- `Runic.Translations.Wpf` binds generated messages in XAML. `TranslationSource`
  wraps a manager and the generated `text.Messages` surface;
  `{rt:Message orders_greeting, Arg0={Binding UserName}}` binds plain messages
  (a named long form, `<rt:MessageInput Name=... Value=.../>`, has no input
  limit), and `rt:TranslationProperties.RichMessage`, `Slots`, `Arguments` and
  `Source` render messages with markup into a `TextBlock` through
  `WpfInlineRenderer`. `Slots` takes the generated typed slots object.
  Bindings refresh on the right dispatcher and hold their elements weakly. See
  the new "WPF quick start" in the package README.

## Optional build-time XAML checks

- `Runic.Translations.Build` can now check static `{rt:Message}` declarations
  and `rt:TranslationProperties.RichMessage` keys against the generated readable
  catalog. It checks exact keys, input counts, readable C# parameter names and
  content kind, with errors at the XAML file and line. `Message` accepts plain
  text; `RichMessage` accepts inline rich content. Document messages need their
  document renderer. `Page` and `ApplicationDefinition` items are collected
  automatically in .NET 10+ WPF projects. No CLI invocation or translation
  artifact emission is needed.
- For a local generating `TranslationProject`, assert the catalog used by the
  application's default source with `TranslationsXamlCatalog` (the `catalog`
  value in `runic.json`):

  ```xml
  <PropertyGroup>
    <TranslationsXamlCatalog>app</TranslationsXamlCatalog>
  </PropertyGroup>
  ```

  A file declaring `Message.Source` or `TranslationProperties.Source`, including
  a source setter, skips the project-default catalog checks. To assert its local
  catalog explicitly, use `<TranslationXaml Include="Views/Checkout.xaml"
  Catalog="app" />`. `Binding.Source` still selects binding data and does not
  disable catalog checks.
- Errors are `RTR0080` for invalid declarations or catalog assertions,
  `RTR0081` for unknown readable keys, `RTR0082` for mismatched or invalid inputs,
  and `RTR0083` for incompatible message content kinds. The scanner reuses the
  compiler's readable names and message contracts; the runtime API is unchanged.
- Catalog assertions describe the source your application supplies; they do not
  create or resolve it. Runtime-valued keys, input names/collections and binding
  results retain runtime validation. External or precompiled catalogs are not
  inspected. Without a catalog assertion, only provable declaration mistakes
  are checked. Set `TranslationsValidateXaml=false` to disable the optional scan.

## Runtime

- New `ITranslationSnapshotNotifier` with `SnapshotPublished` (and `TranslationSnapshotPublishReason`), implemented by
  `TranslationManager`. It is raised after every published snapshot: a locale
  switch (together with `LocaleChanged`) and each `RefreshAsync`, which still
  never raises `LocaleChanged`. UI layers can follow refreshes without polling.
