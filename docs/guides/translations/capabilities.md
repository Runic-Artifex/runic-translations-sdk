The table lists every CLDR language and script locale. A regional or script variant such as `de-CH`, `pt-AO` or `zh-TW` has the capabilities of the locale it resolves to:
its CLDR data ID adds the likely script (`zh-TW` is `zh-Hant-TW`), plural rules are looked up by removing subtags (`pt-PT` has its own rules, `pt-AO` uses `pt`'s),
and list patterns and relative time follow CLDR's parent locales (`pt-AO` uses `pt-PT`'s, `es-MX` uses `es-419`'s).
A language without CLDR ordinal rules selects `other` for every ordinal, and a locale with CLDR data but no plural rules of its own (`agq`, `rw`, `mi`) selects `other` for every number (CLDR's root rule).
Only languages without CLDR data, such as `tlh`, fail compilation with `RTR0031` when a message selects on plurals or formats a list or relative time.
Cardinal selector equivalence: **exact**.
Ordinal selector equivalence: **exact**.
Relative-time equivalence: **exact**.
List equivalence: **exact**.
Plural selection, relative-time and list patterns are generated from the pinned CLDR subset; the ESM backend does not delegate them to host `Intl` data.
Relative time formats its number as `:number` does by default, in the formatting locale and from the pinned CLDR number formats (symbols, grouping and digits), so it is exact too.
Numbers and percentages use the pinned CLDR number formats of the formatting locale in both backends; localized dates and times use platform data, so they stay semantic.
`:currency`, `:unit` and compact notation (`:number runic:notation=compact`) use pinned CLDR currency, unit and compact data for every locale in the table, so they are exact too; the compiler embeds only the currencies, units and compact styles a catalog uses, for the catalog's languages (see [currencies, units and compact numbers](rmf2.md#currencies-units-and-compact-numbers)).
For the CLDR locales the JavaScript engines have no date data for, listed in `specs/translations/corpus/localized-format-engine-coverage.json`, ESM dates use the nearest CLDR parent the engine has (else `en-US`) and .NET its ICU's fallback, so their dates can differ between the backends.
Cardinal and ordinal rules use all CLDR operands of the displayed number, after percent scaling, rounding and minimum fraction digits.

## Formatter equivalence

| Formatter  | Forms                                                  | Equivalence |
| ---------- | ------------------------------------------------------ | ----------- |
| `string`   | `default`                                              | exact       |
| `boolean`  | `default`                                              | exact       |
| `integer`  | `plain`, `grouped`                                     | exact       |
| `number`   | `plain`, `grouped`, `fixed`, `percent`                 | exact       |
| `date`     | `iso`                                                  | exact       |
| `date`     | `localized`                                            | semantic    |
| `time`     | `iso`                                                  | exact       |
| `time`     | `localized`                                            | semantic    |
| `datetime` | `iso`, `localized`                                     | semantic    |
| `uuid`     | `d`, `n`                                               | exact       |
| `currency` | `symbol`, `narrowSymbol`, `code`, `name`, `accounting` | exact       |
| `unit`     | `short`, `long`, `narrow`, `compound`                  | exact       |
| `compact`  | `short`, `long`                                        | exact       |

**Exact:** Backends produce the same canonical value for every accepted portable input.

**Semantic:** Backends preserve meaning but platform globalization can change punctuation, spacing, names, or representable decimal precision.

This release deliberately claims only the locales above.
A platform may recognize other BCP 47 tags for scalar formatting, but they are
not part of the cross-runtime support promise until they appear in the matrix
and shared .NET/ESM conformance fixtures.
