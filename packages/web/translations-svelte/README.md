# `@runic-artifex/translations-svelte`

Svelte 5 helpers for Runic Translations locale state and RMF2 inline and
document content.

```ts
import { createLocaleContext } from "@runic-artifex/translations-svelte";
```

`useMessageLocale(locale)` from the package root makes the generated `m.*()`
calls of every catalog on the page, the application's and its libraries', follow
a locale the application owns: a `SvelteLocale` from `localeContext.provide`, or
a getter over a ViewModel's setting. Templates update in place when it changes.
Call it once in the root layout. It sets the generated runtimes' shared locale
channel, which every catalog generated by Runic Translations 0.9 or later reads
when it has no resolver of its own; each catalog resolves the tag under its own
locales, so a library that lacks the locale shows its fallback. A `SvelteLocale`
passes its requested tag (`de-CH` for `de` text), so numbers and dates follow the
requested region. Resolvers are removed by identity when their component is
destroyed, so the latest one still mounted applies, in whatever order
components are destroyed. During server rendering it installs nothing, as the
channel is process-wide: the request's locale comes from the generated
`runWithLocale` (SvelteKit's `createLocaleHandle` sets it), so concurrent
requests stay isolated, and a server without it renders the base locale unless
a call passes `{ locale }`. `useMessageLocale(configureLocaleResolver, () => locale)` sets one
catalog's own resolver only, as before 0.9. The
`./inline` and `./document` components work in any Svelte 5 app built with Vite,
with or without SvelteKit; see
[Svelte without SvelteKit](https://github.com/Runic-Artifex/runic-translations-sdk/blob/main/docs/guides/translations/quickstart-vite.md#svelte-without-sveltekit).

The browser-safe `@runic-artifex/translations-svelte/testing`
entry point provides pseudo-localization, RTL isolation, plural boundary values,
and accessibility stress fixtures. `@runic-artifex/translations-svelte/inline`
exports `LocalizedInline` and `inlineFactory` for localized structured content.
`@runic-artifex/translations-svelte/document` exports `LocalizedDocument` and
`documentFactory` for RMF2 document messages: semantic paragraphs, headings and
lists that hydrate by occurrence path, with no inline styles. Pass
`documentFactory` to the catalog's `createDocumentRenderer` once, then render
its output with `<LocalizedDocument {nodes} />`. A top-level block whose content
locale is written in the other direction than the page gets `dir` beside `lang`;
the page has the provided locale's direction (`SvelteLocale.direction`, the same
as `%runic.dir%`, else left to right) unless you pass `pageDirection`, and
`textDirection(locale)` from the package root gives a locale's direction (see
[right-to-left text](https://github.com/Runic-Artifex/runic-translations-sdk/blob/main/docs/guides/translations/bidi.md)). The document block set is open: a later minor release may add blocks, and the renderer fails on a block name it does not know, so update the adapter with the compiler. Inline binding kinds (`runic:link`, `runic:action`, `runic:icon`) are closed. See
[Web document adapters](https://github.com/Runic-Artifex/runic-translations-sdk/blob/main/docs/guides/translations/rmf2.md#web-document-adapters).
